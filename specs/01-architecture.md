	# Spec 01: Site Architecture

**Status:** implemented
**Created:** 2026-03-13
**Depends on:** none

---

## Goal

Define the technology stack, folder structure, and data pipeline that all other specs will build on.

## Context

The site replaces an existing Google Sites page. Source content is JPEG photos organized in folders on OneDrive. The folder structure encodes all kit metadata (name, scale, manufacturer, category). No database or CMS exists — the file system is the data source.

## Technology Stack

| Concern | Choice |
|---------|--------|
| Site generator | [Eleventy (11ty)](https://www.11ty.dev/) |
| Languages | HTML, CSS, JavaScript |
| Dev server port | 8080 |
| Output folder | `dist/` |

## Folder Structure

```
ScaleKits/
├── src/
│   ├── _data/          ← kit metadata (generated by import script)
│   ├── _includes/      ← HTML templates and partials
│   └── index.njk       ← main page template
├── public/
│   └── images/         ← kit photos copied from OneDrive (one subfolder per kit)
├── scripts/
│   └── import.js       ← import script: copies and renames images from OneDrive
├── dist/               ← generated site output (not committed to git)
├── .eleventy.js        ← Eleventy configuration
└── package.json
```

## Inputs

| Input | Type | Source | Notes |
|-------|------|--------|-------|
| Kit photos | JPEG images | OneDrive `__Public data/` | ~329 files, 640KB–2.7MB each |
| Kit metadata | Folder/file names | Same folder | Name, scale, manufacturer, category encoded in path |
| Category groupings | Folder prefixes | See category mapping table below | |

## Outputs

| Output | Description |
|--------|-------------|
| Static website | HTML/CSS/JS files in `dist/`, openable in a browser |
| `public/images/` | Kit photos copied and renamed from OneDrive |
| `src/_data/kits.json` | Kit metadata extracted from folder/file names during import |

## Folder and File Naming Convention

All kit folders in `public/images/` follow this format after import:

```
Name_Scale_Manufacturer/
  _box.jpeg       ← box art photo
  _01.jpeg        ← build/detail photos (numbered)
  _02.jpeg
  ...
```

Example: `Spitfire-Vb_1-72_Revell/`

- Separator between fields is `_` (underscore)
- Spaces within a field are replaced with `-` (hyphen)
- Scale is written as `1-72`, `1-48`, etc. (slash replaced with hyphen)

## Category Mapping

| OneDrive path | Category ID | Display name | Notes |
|---|---|---|---|
| Root folders (no prefix) | `progress` | Kits in Progress | Kit folders with build photos |
| `_Finished Kits/` | `finished` | Finished Kits | Completed builds |
| `_Mid Age Kits/` | `mid` | Mid Age Kits | Kit folders with build photos |
| `_Early Age Kits/` | `early` | Early Age Kits | Kit folders with build photos |
| `_Stash/` root files | `stash` | Stash | Loose JPEG files, box art only |
| `_Stash/_Figures & Material/` | `figures` | Figures & Material | Loose JPEG files, box art only |
| `_Stash/_Stash No More/` | `stashnomore` | Stash No More | Kits no longer owned; loose JPEG files, box art only |

**Stash-type categories** contain loose JPEG files (no subfolders), with metadata encoded in the filename using the same `Name_Scale_Manufacturer` convention. Box art only, no build photos.

**Renaming happens only during import into `public/images/`.** OneDrive source files are never modified.

## Data Pipeline

1. The import script (`scripts/import.js`) reads kit folders from the OneDrive source path.
2. It renames folders and files to the standard convention and copies them into `public/images/`.
3. It extracts kit metadata (name, scale, manufacturer, category) from folder/file names.
4. It writes all metadata to `src/_data/kits.json`.
5. Eleventy reads `kits.json` and renders the site into `dist/`.

### Metadata resolution rule

When a folder or filename cannot be reliably parsed (scale concatenated with name, folder named "Box only", or any other ambiguous case):

1. Read the box art image from inside the folder.
2. Search [scalemates.com](https://www.scalemates.com) to identify the exact kit.
3. Use the scalemates.com data as the authoritative source for name, scale, and manufacturer.

This lookup is performed manually by Claude during the first import, one kit at a time. Results are written directly into `src/_data/kits.json`.

The **first import** is run once by the developer (Claude) during initial setup. Subsequent imports use the `npm run import` command.

## Acceptance Criteria

1. Running `npm run build` produces a working website in `dist/`.
2. The site loads in Chrome, Firefox, and Safari without errors.
3. All 104 kits are represented on the site after a build: 11 in progress, 4 finished, 13 mid age, 15 early age, 43 stash, 13 figures & material, 5 stash no more.
4. Kit name, scale, and manufacturer are correctly parsed for every kit and every Stash item.
5. The site is accessible at `http://localhost:8080` when running `npm run serve`.
6. `public/images/` folders follow the `Name_Scale_Manufacturer` naming convention after import.
7. OneDrive source files and folders are not modified by the import script.

## Out of Scope

- A CMS or admin interface for editing kit data
- User accounts, comments, or any server-side logic
- Mobile app
- Hosting / deployment target (decided in a future spec)

## Open Questions

_None — all resolved._

### Decisions made

- **Tech stack:** Eleventy (11ty) static site generator.
- **Images:** Copied into `public/images/` by the import script. OneDrive originals are never touched.
- **Naming:** Folders and files are renamed to `Name_Scale_Manufacturer` convention during import only.
- **First import:** Performed by Claude during initial setup. Future imports use `npm run import`.
- **Stash:** Shown on the site. Box art only. Metadata parsed from filenames.
- **Hosting:** Out of scope for this spec. Decided later.
- **Dev port:** 8080 (Eleventy default).
